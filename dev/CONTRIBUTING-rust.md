# Working on tidyABM's Rust code

tidyABM is moving its engine to Rust under the unchanged R grammar. The plan, its
decisions and the phase results live in `sandbox/rust-migration/PLAN.md` (outside
this repository). The work lives on the `rust` branch until phase 4; `main` stays
pure R.

## Layout

| path | what |
|---|---|
| `src/rust/Cargo.toml` | the savvy bridge crate `tidyabm` (R entry points) and the workspace |
| `src/rust/src/lib.rs` | the `#[savvy]` entry points; each body runs under `run()` (panic guard) |
| `src/rust/src/rapi.rs` | hand-written declarations of R's public C API (RNG, Rmath) and of `src/reduce.c`; `protect()` |
| `src/rust/src/rng.rs` | `with_rng()` / `RRng`: R's own generator from Rust, main thread only |
| `src/rust/src/reduce.rs` | safe wrappers over the long-double C helper |
| `src/rust/src/store.rs` | the column store's R side (`AgentStore`): loading groups, exporting them, the write API `set_col()`, the string pool, the mirror cache, snapshots, stacking the result |
| `src/reduce.c` | long-double sums, means, cumsums, group sums (Rust has no long double) |
| `src/rust/tidyabm-core/` | engine code with no R dependency; `cargo test` runs here (`sample.rs`, `reduce.rs`, `store.rs`, `neighbours.rs`, `expr.rs` the evaluator) |
| `R/rust-blocks.R` | `rust_rng_ok()` (verified `RNGkind()`s) and the R-side wrappers with their R fallbacks |
| `R/run-rust.R` | the Rust run path: `run_once_rust()`, the step adapter, kernel dispatch and replay (`rust_step()`), "both" mode |
| `R/rust-kernels.R` | the kernel registry `rust_kernels` |
| `R/rust-expr.R` | the expression compiler (`rx_compile()`, `rx_program()`), `rx_coverage()` |
| `R/run-loop.R` | the Rust-driven run `run_once_loop()`, native-step compilers `rl_prep_*()`, kernel `rk_native()` |
| `src/rust/src/runloop.rs` | `RunLoop` (the tick loop, R callbacks), the native executors, `rs_native_exec()` |
| `src/rust/src/expr.rs` | `RxProgram`: decodes the IR, reads R's columns in place, R callbacks for draws and `exp`/`log`/`sqrt` |
| `src/rust/Cargo.lock` | pinned crate versions (committed) |
| `src/rust/vendor.tar.xz`, `vendor-config.toml` | all crates for the offline build (committed) |
| `src/rust/deny.toml` | licence / advisory policy for cargo-deny (CI) |
| `src/Makevars.in`, `Makevars.win.in` | build templates; `configure` / `configure.win` fill them |
| `src/init.c`, `src/rust/api.h`, `R/000-wrappers.R` | generated by `savvy-cli update`; do not edit |
| `R/engine-switch.R` | `options(tidyABM.engine = )` and `rust_call()` (Rust errors to R conditions) |
| `tools/vendor.sh` | rebuilds `vendor.tar.xz` and `inst/AUTHORS` |
| `dev/oracle/` | the frozen oracle every migration step is checked against |

## Toolchain

* Rust through rustup (<https://rustup.rs>), stable channel. The minimum supported
  version is 1.81 (`rust-version` in both `Cargo.toml`; savvy 0.11 needs it). CI
  builds with 1.81 too.
* `savvy-cli` 0.11.0, the same version as the `savvy` crate:
  `cargo install savvy-cli --version 0.11.0 --locked`. It ends up in
  `~/.cargo/bin`; put that on `PATH` or call it by its full path.
* R >= 4.2 and the usual devtools set.

## Everyday loop

```sh
# after changing an entry point's signature or adding one (src/rust/src/lib.rs):
savvy-cli update .                    # from the package root
# load and test from R (builds the Rust library into src/, about a minute the first time):
Rscript -e 'devtools::load_all(); devtools::test()'
# Rust only (from src/rust):
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p tidyabm-core
```

`load_all()` decides whether to recompile from the C files in `src/` only, so after
editing `.rs` files run `touch src/init.c` before the next `load_all()`; otherwise it
keeps the old library. **`load_all()` builds the Rust library unoptimised** (pkgbuild
passes `DEBUG=true`, so `configure` picks cargo's `dev` profile): Rust code then runs
10-20x slower (the neighbour fold: 100 us instead of 6). Before timing anything, and
in any shell that runs the oracle, `export SAVVY_PROFILE=release` and rebuild
(`touch src/init.c`); `grep PROFILE src/Makevars` says which one the last build used.
Any later `load_all()` that recompiles without that variable goes back to `dev`. Avoid `pkgbuild::clean_dll()`: it also deletes the `.a` files
that cargo's build scripts left under `src/rust/target` (savvy's
`libunwind_protect.a`), and the next build fails with "could not find native static
library `unwind_protect`" until `src/rust/target` is removed.

Run `cargo clippy` / `cargo build` with a target directory of their own
(`CARGO_TARGET_DIR=/tmp/tidyabm-target cargo clippy ...`): a dev build in
`src/rust/target/debug` can leave a `libtidyabm.a` that the next `load_all()` links
without savvy's C helper (`symbol not found: _unwind_protect_impl`); deleting
`src/rust/target/debug` fixes it.

The savvy crate's own tests do not link without an R session; test entry points
from R (`tests/testthat/test-rust-*.R`) and keep logic in `tidyabm-core`.

Rules the code follows (PLAN.md section 1):

* Every `#[savvy]` body runs inside `run(|| ...)`. It installs a silent panic hook,
  catches the panic and returns its message as an error, so a panic becomes the R
  condition `tidyABM_rust_panic` and never unwinds into R. savvy's own hook prints
  through R from whichever thread panicked, which is forbidden on worker threads.
* No R API call from a worker thread. Workers get plain Rust data; results and
  panics come back through `join()`.
* Rust never formats what the user reads. It returns an error message with a prefix
  (`ERROR_PREFIX` / `PANIC_PREFIX` in `tidyabm-core`); `rust_call()` in R raises it
  with `abm_abort()` and a class.
* Every `unsafe` block has a `// SAFETY:` comment.
* **No code copied or ported from R's sources** (GPL; decision D13, the package is
  MIT). R's generator and math are reached only through R's public C API
  (`GetRNGstate`/`PutRNGstate`, `unif_rand`, `norm_rand`, `exp_rand`,
  `R_unif_index`, the Rmath `Rf_r*` functions, `R_pow`), declared by hand in
  `rapi.rs`. Behaviour that is not in the API (the long-double sums, mean's second
  pass, `sample.int()`'s algorithms) is written from R's documentation and pinned
  down by differential tests against R, never by reading R's C sources. Where
  neither works (weighted `sample()`, R >= 4.5's `exp`/`log` wrappers), the R path
  is used.
* R's RNG only inside `rng::with_rng()`: it loads the state with `GetRNGstate()`,
  hands out the `!Send` token `RRng`, and writes the state back with
  `PutRNGstate()` on every exit (return, error, panic). Never draw on a worker.
* Any call that may raise an R error or warning (`GetRNGstate`, `PutRNGstate`,
  Rmath functions, `R_pow`, which warns for huge exponents) goes through
  `rapi::protect()`: a warning turns into a longjmp under `options(warn = 2)` or an
  exiting `tryCatch(warning = )`, and a longjmp must never cross Rust frames.
* The Rust path draws only under the `RNGkind()`s the tests verified
  (`rust_rng_ok()`); every other kind, and every parameter for which R would warn,
  takes R's own function.

## The engines and the column store (phase 3)

`options(tidyABM.engine = )`: `"r"` (default) is the R engine; `"rust"` keeps the
run's groups in the Rust column store (`AgentStore`) and runs each step through its
Rust kernel (`R/rust-kernels.R`) or, while none exists, through the *step adapter* (the R engine's step
function over the store's groups, loaded back afterwards); `"auto"` takes the Rust
path only when some step has a kernel registered with `auto = TRUE`; `"both"` runs every step on the R engine and
on the Rust path from the same state, `.Random.seed` and caches, and stops at the
first difference (`tidyABM_engine_mismatch`, naming step, tick, group, column, row
and both values). A kernel is `function(step, state, store)` registered in
`rust_kernels` (`R/rust-kernels.R`) under the step's class; test it with
`TIDYABM_ENGINE=both` over the test suite and the oracle (`TIDYABM_ENGINE=both
./scripts/verify.sh`, the same for `models.sh`).

Store rules: doubles, integers and logicals keep their bits; a character column is
codes into a pool of R's own `CHARSXP`s; a typed column's attributes (factor
levels, classes, names, dim) live on a zero-length donor and come back with
`SHALLOW_DUPLICATE_ATTRIB()`; list, complex, raw and data-frame columns are opaque
preserved R objects. Every column, group and the group list keep the R object they
came from (the mirror): `export()` hands it back while Rust has not changed the
column, and `load()` copies only columns whose object changed. `set_col()` drops the
written column's, its group's and the list's mirrors in one place.
Results are stacked in Rust when every column is a plain typed vector of one type,
otherwise by R's own `bind_rows()` over the recorded groups.

## Step kernels (phase 4)

A kernel is `function(step, state, store)` in `R/rust-kernels.R`, registered in
`rust_kernels` under the step's class with `auto = TRUE` only once it is proven in
"both" mode **and** measured faster than the R engine on paired runs. Rules:

* Follow the R engine's step function line for line where it does R work (same
  helpers, same `planned()` keys, same `state` fields such as `nb_cache`): "both"
  compares the whole `state`, not just the groups.
* Decline (`return(NULL)`) before changing anything for any shape the kernel does
  not take; the step then runs through the adapter from the original state and
  `.Random.seed`.
* Write columns only through `store$set_col(group, name, values)` (it drops the
  column's, the group's and the list's mirrors), then set
  `state$groups <- store$export()`. `values` must be what `assign_rule()` would
  have written over every row (bare, unnamed, one value per row).
* Never print. Outside "both", a kernel that errors, warns or messages is replayed
  on the R path (`rust_step()`), so the user sees R's own condition exactly once;
  under "both" the same thing is a mismatch, so kernel faults are caught, not hidden.
* `options(tidyABM.rust_kernels = c(neighbours = FALSE))` turns a kernel off
  (step class without `abm_`).
* Rust code reads R vectors through `store::numbers_of()` (no copy; ALTREP data is
  materialised inside `protect`) and returns `NULL` (decline) for anything it does
  not handle bit for bit (for example sums that meet `NA`/`NaN`, whose payload choice
  is `rowsum()`'s).

The store outside "both" is brought up to date only when read: the adapter marks it
stale (`sync$ok`), and `run_once_rust()` loads `state$groups` before a kernel or a
recorded snapshot. Under `use_mirror` a loaded typed column is kept as R's vector and
copied into Rust only for a snapshot that may reach the result (lazy copy-in).

## Compiled formulas (phase 5)

`abm_rules()` (no `.by`, nothing read of a pairing, no relation) and `abm_global()`
(no `.by`) run natively inside the Rust tick loop (next sections) when a formula of
the step is in the grammar of `R/rust-expr.R` (see its header and `rx_coverage(go)`
for the reason a rule is not). An `abm_rules()` step may mix compiled rules with
rules R evaluates (user functions, `Map()`, ...): `rl_rule_fns()`'s `rule_fn` is
called for those in rule order (the native rules in between draw in the same
order); once an R rule has run its effects stay, so a later native decline does not
replay the step but hands that rule and the rest to R from the stream before it
(`rng_save`/`rng_restore`). Values from the formula's environment are read every
step through `scope_fn` (as the R engine reads them). Under a standing match with
pairs, a match-scope step of elementwise rules writes only the placed agents
(`assign_rows()`: vctrs' common type of column and value); other rules go to R.
How it fits together:

* `rx_compile()` turns a formula into nested lists once per session; `rx_program()`
  binds names to input slots for a group (column, then global, then the formula's
  environment, as the R engine's mask finds them), checks that every function name
  finds the standard function, and builds an `RxProgram` (kept per session).
* `RxProgram$eval(inputs, n, out_n, stacked)` evaluates the rules in order and
  returns R vectors, or `NULL` with the reason in `rs_rx_reason()`. Rust never
  warns: wherever R would warn, error or give bits Rust cannot reproduce exactly, it
  declines and the loop replays the step on the R path from the saved state and
  `.Random.seed`. The loop calls `RxProgram::compute()` directly on the state's
  column vectors (`src/rust/src/runloop.rs`).
* Typing is R's and vctrs', decided per call from the data (`tidyabm-core/src/expr.rs`).
* `rl_prep()` returns `FALSE` for a step whose formulas can never compile (it
  then always runs in R); `can(step)` tells "auto" whether a run has anything a
  kernel can take.

A pure base function whose bits only R's own code gives (`^`, `abs`, `round`,
`cumsum`, `min`/`max`, `%%`, `as.integer`, ...) is not reimplemented: list it in
`rx_call_spec` (arity, and whether it can warn) and the evaluator calls R's own
function on the evaluated numeric arguments (`Node::Call`); one that can warn is
called through a guard that turns any condition into a decline (`%%` warns about
lost accuracy for large operands: found by the property test).

Adding a function to the grammar: add it to `rx_fns()` and `rx_compile()` (R), to
`decode()` (`src/rust/src/expr.rs`) and to `Node`/`eval()` in
`tidyabm-core/src/expr.rs` with a cargo test; then extend `rx_random_expr()` in
`tests/testthat/test-rust-expr.R` so the property test (3,000 random formulas with
`NA`, `NaN`, `Inf`, `-0`, integer extremes, strings) covers it, and run the suite
under `TIDYABM_ENGINE=both`. Behaviour comes from R's documentation and
differential tests only (D13): for example, integer `/` gives R's `NA_real_` for an
`NA` operand, `pmin(0, -0)` keeps the first, dplyr 1.2's `case_when()` sizes its
conditions and values apart. Measure with `SAVVY_PROFILE=release`: an R-driven
kernel step cost ~25-30 us of R-side overhead (phase 5); a native step in the Rust
loop costs ~5-10 us of overhead plus its evaluation.

## Vendoring (offline builds)

`R CMD INSTALL` builds offline from `src/rust/vendor.tar.xz` whenever that file
exists (`cargo build --offline -j 2` with a private `CARGO_HOME`), as CRAN requires.
So **after changing any dependency or `Cargo.lock`, re-vendor**, or the install
fails:

```sh
sh tools/vendor.sh                    # from the package root; needs network once
```

It rewrites `vendor.tar.xz`, `vendor-config.toml` and `inst/AUTHORS` (crate, version,
licence). Check that every licence is MIT or Apache-2.0 compatible; CI's `deny` job
checks it with cargo-deny (`cargo deny check` in `src/rust` if you have it installed).

```sh
CARGO_HOME=/tmp/empty-cargo-home R CMD check --as-cran --no-manual tidyABM_*.tar.gz
```

## The Rust tick loop and native steps (full-Rust stages)

A run with a step that a *native* kernel takes (`native` in `rust_kernels`) runs
with its tick loop in Rust: `run_once_loop()` (`R/run-loop.R`) builds the state
and the R callbacks, `RunLoop` (`src/rust/src/runloop.rs`) owns the state list for
the whole run. Native steps (today `abm_rules`/`abm_global` in the compiled
grammar and network `abm_neighbours` `sum`/`mean` of bare double, integer or
logical columns) run without any R code; every
other step, and each run of consecutive such steps, is one callback (`seg`) into
the R engine's own `run_step()`. Rules:

* The state stays the R engine's list; columns are R vectors read in place.
  Native code **never modifies an R object in place**: it commits new vectors into
  shallow copies of the containers (`with_elt()`, `set_named()`), so any R variable
  that still holds the old state is untouched.
* A native step is compiled by an R callback (`rl_prep()`: descriptor, `NULL` = R
  for this schema, `FALSE` = never) and cached against the schema key
  `c(length(globals), lengths(groups))` (+ edges and agent count for neighbours).
* Transactional: evaluate everything, then commit. A decline returns `None`
  without touching the state; the loop then replays the step on the R path, after
  restoring the `.Random.seed` saved before any drawing native step.
* Every R call that can allocate or raise goes through `rapi::protect` (or
  `build()`, which also keeps the new object before anything else allocates).
  `getAttrib(x, names)` on a list is the one call made outside it (it neither
  allocates nor raises there). `ATTRIB()`/`OBJECT()` are not API: attributes are
  checked with `all_bare()` (copy onto an empty vector, `R_compute_identical`).
  `expr::to_r()` returns its new vector *unprotected*: store it at once into a
  list that already exists (`OwnedListSexp::set_value`), never allocate the
  holder after it (that freed a column now and then in 0f61deb's neighbour
  commit; `TIDYABM_GCTORTURE=run` runs a `gctorture()` test of the native steps).
* Rules/global descriptors are memoised for the session (`rl_prep_memo()`,
  keyed by the step's rules, the state's names, function-valued globals,
  `RNGkind()`), so a sweep compiles each step once.
* "both" mode runs the same executor step by step (`rk_native()` ->
  `rs_native_exec()`) against the R engine; the loop itself is checked by result
  identity with "r" (tests, oracle, models/). `.rl_last$stats` holds the last
  loop's counters: native steps run, declined, compiled, R callbacks.
* Neighbour kinds: 3 network `sum`/`mean` of compiled elementwise arguments
  (`neighbour_fast()`'s shapes; descriptor also keyed by edges and agent
  count), 5 `within = <col> == own_<col> [& rest]` with one candidate each
  (`nb_one()`'s shapes, Wolf-Sheep's lookup; columns stacked as `vec_rbind()`
  pads them, `stacked_pad()`), 6 `.where = <direction>` on a lattice
  (`directional_view()` + `neighbour_aggregate()` over neighbourhoods of one).
  The cross-product `within` (`attribute_view()`) and relations still run in R.
* Match (kind 7): `random`/`one_of`/`opposite_group`/`network` without `weight`,
  `cost`, pairwise `among`, with roles (two named conditions that must not
  draw); `opposite_group` also with a number `.by` (`match_by_opposite()`).
  `eligible`/`among`/role conditions are one program over the groups stacked;
  draws (`shuffle()` = `sample.int(n)` without replacement, `sample.int(n, k,
  TRUE)`, the role coin `runif`) come from R's generator in R's order. The
  table is built as `new_match()` builds it (`match_table()`). Rules read the
  standing match natively (`.partner`, `.role`, `.group_id`, `partner_<col>`:
  input source 4, `match_inputs()`), and a non-elementwise rule under a
  match-scope match runs once per `.group_id` (`eval_by_key()`'s order).
* Death (kind 8) and birth (kind 9, `when =` without `attach_via`): conditions
  and `times`/`cost`/`inherit` as programs over the rows R evaluates them over;
  rows sliced (`slice_group()`) and offspring appended (`append_rows()`'s
  `c()`), ids from `state$next_id`. Edge pruning and relations go to R.
* Move (kind 10): `to = "random_neighbour"` / `"random_empty_neighbour"` (or
  `avoid_occupied`), `range = 1`, on the lattice (`along` its group or
  `"network"`): `run_move()`'s mover order (`sample.int(n)`), batch draw or
  per-mover draws, occupancy counts, then `sync_cell_coords()` (`.x`/`.y` from
  the lattice; a bad `.cell` is R's error). Direction, `range > 1`, `axes_only`,
  uphill/downhill: R.
* Tell (kind 11): `to = <id expression>` with `.resolve` last/first/sum/mean
  (error is R's), no `.order`; `when`, `to` and the messages one program over
  the groups stacked; writes in vctrs' common type (`replace_at()`). `to =
  "neighbours"`, list recipients, `collect`/`max`/`min`, `partner_` reads: R.
* Sequential (kind 12, `exec_seq()`): every rule compiled; per group one
  program over the rules `applicable_rules()` routes to it, evaluated agent by
  agent (`expr::Evaluator`: one RNG scope for the whole step, never a nested
  `with_rng()`, which would reload the generator and lose draws). Inputs borrow
  the agent's row from a per-step column store; a rule's value replaces its
  input slot (`wslot`) for the rules after it, as `data[[target]] <-` does;
  writes to the store and the globals are applied after the agent's rules (no
  rule of the same agent reads them back). A write is cast only where vctrs'
  common type is the column's own (`seq_cast()`); one that would change the
  column's type, a new column, relations, a `.cell` target, rules R must
  evaluate: R. Order: `shuffle()` over the ids (narrowed by a standing match),
  or `.order` compiled over the groups stacked, stable, `NA` dropped (`-0` ties
  `0`, as `order()`'s radix sort). Partner reads are live (`NA` logical with no
  partner or a partner group without the column).
* Repeat blocks (FR11): `rl_flatten()` puts an `abm_repeat()`'s steps into the
  loop's step list between a begin marker (kind -1) and an end marker (kind
  `-(2 + 2 max + has_until)`), both the repeat step; the loop jumps back from
  the end until `max` passes or `until` holds. `until` is a value-only program
  per schema in the end's slot when it compiles (`rl_prep_until()`), else the R
  callback `until(k)` ([repeat_until()], which raises R's errors). The match
  standing at the begin is restored at the end (`state$match <- outer_match`:
  removed when there was none). Errors in a block's steps are reported as
  `run_repeat()` reports them (`top_at` is `NA` inside a block).
  `engine_run_once()` counts the steps inside blocks.
* Global `.by` (kind 13, `exec_global_by()`): keys from a global or a
  formula-environment value (a key column, sorted and merged with the global's
  names, is R's), integers or strings; per rule one program over the groups
  stacked, the target and `.key` bound per key as input source 4; the named
  vector built as `out[[key]] <- val` builds it (`gby_assign()`: logical <
  integer < double promotion, strings only with strings).
* Births (FR12): `attach_via` from a parent or to random agents
  (`attach_draws()`, after every group's births, one RNG scope; edges of
  `from`/`to` only, extended as `vec_rbind()` does); `n =` (`exec_birth_count()`:
  templates drawn from the first group, rules over the template rows when none
  reads an id, a group or an earlier target). Deaths drop the dead's edges
  (`slice_tibble()`). `random_edge` stays R.
* Cross-product `within` (kind 14, `exec_cross()`): per focal agent, `within`
  over all candidates (`own_` columns as one value), then each rule over the
  kept rows: `neighbour_aggregate()`'s shapes on logicals/integers (doubles go to
  R: `rowsum()`'s accumulation is not pinned down on x86), any other formula as
  `summarise()` evaluates it. `abs()` is native (FR12).
* Match `nearest` on one coordinate (FR13, pair code 5): `(a^2 + b^2) -
  2 * (a * b)` per chooser and candidate, exact for one column, the first of
  ties; several coordinates stay R (BLAS summation order). Network neighbours
  where every rule is `any()`/`all()` of an elementwise argument over the
  candidate (`exec_nb_anyall()`, loop kind 15 so the slot is not keyed by the
  edges): the neighbours read off the edges both ways round; `state$nb_cache`
  rebuilt natively as `list(edges, nb = neighbour_table(edges))` whenever R
  would (`identical()` of the cached edges, `R_compute_identical`), else left
  as it is; a mix with `sum`/`mean` stays R (`rowsum()`). The step plan key is
  `rl_nbshapes` (the R engine's `neighbour_fast()` owns `shapes`).
* Moves along a heading (FR13): `direction =` compiled per moving group (no
  draws: it is evaluated after the movers' order is drawn), `heading_names()`
  natively (strings lowered, numbers `round()`ed half to even, `%% 4`), then
  `dir_nb` per mover in the drawn order, occupancy as R counts it.
* Edge draws, network-view neighbours, and gradient/`range` moves (FR14):
  `abm_draw()` (kind 16, `exec_draw()`) evaluates rules over non-draw edge
  columns once per edge (or twice for `.each = "endpoint"`) inside one RNG
  scope, commits `.draw_<t>`/`.back_<t>` on shallow copies of `state$edges`, and
  clears `state$stale_draws`. Network `abm_neighbours()` with `own_<col>`,
  edge-draw columns (`<name>`, `<name>_back`), `na.rm`, or mixed
  `n()`/`sum()`/`mean()`/`any()`/`all()` runs natively as kind 17
  (`exec_nb_view()`): evaluates arguments over the `(focal, neighbour)` view,
  aggregates integer/logical sums/means (declining doubles for `rowsum()` parity,
  using `reduce::mean_int(&[])` for all-`NA` `0/0` NaNs) and `any`/`all`/`n()`,
  and rebuilds `state$nb_cache` when stale. `abm_move()` (kind 10) now handles
  `range > 1`, `axes_only = TRUE`, and `uphill()`/`downhill()` natively: per
  moving group's compiled expression (with mover-over-patch shadowing and `own_`
  columns) evaluated per mover inside the step's single RNG scope after
  occupancy filtering, matching R's draw interleaving and tie-breaking.
* `pkg::f` heads (`dplyr::case_when()`, `stats::runif()`) compile as `f` when
  they are the very function the IR takes for `f` (`rx_ns_head()`); their
  scope is not checked (the call names its function).
* Parallel reps (FR10): forks (`mclapply()`) on Unix; on Windows (or with
  `options(tidyABM.psock = TRUE)`, for tests) a PSOCK pool per sweep
  (`run_psock()`) set up with the caller's attached packages, `tidyABM.*`
  options and global workspace. Each run carries its seed, so results are the
  serial ones. The PSOCK test is skipped under pkgload (workers load the
  installed package).
* `find_str()` compares names byte by byte against R's buffer (`same_bytes()`):
  every step looks the state's elements up by name, and `strlen()` on each name
  first was measurable on short models.
* Descriptor memo (`rl_prep_memo()`): keyed by the whole step without its
  plan (a match has no rules to tell steps apart by) and the schema.
* Tick book-keeping (FR9): an unrecorded or recorded tick without a progress bar
  is closed in Rust: globals into `glog`, measures/checks as value-only
  global programs (`rl_tick_step()`, `try_tick()`; a decline or a check that is
  not `TRUE` closes the tick through the R callback, which raises R's error),
  a recorded tick's `state$groups` into `slog` (zero copy), stacked once after
  the run by `rs_stack_ticks()` (bare columns of one type throughout; else R's
  `snapshot()` + `bind_rows()`). The logs are written only by Rust: the R
  callback must not assign into them (that would copy the list R reads back).
* A run with no step the loop takes natively runs on the R engine under "rust"
  and "auto" (the store adapter only added conversion cost); "both" still
  exercises the store. A step that declines 8 times in a row stays on R until
  the schema changes (`DECLINES_BEFORE_SKIP`).
* Adding a native step kind: an `rl_prep_<kind>()` in `R/run-loop.R`, a `kind`
  number in the registry (`native =`, with a static `can()`), its executor in
  `runloop.rs` (`exec()` dispatch), a "both"-mode test via
  `expect_engines_agree()` and a loop test asserting `.rl_last$stats`.

## The oracle

`dev/oracle/` holds the frozen goldens (README there). Before and after any change
to engine code, from `dev/oracle/`:

```sh
./scripts/verify.sh                   # tests, 291 harness cases, vignettes, benchmarks (~3 min)
./scripts/models.sh                   # the 68 models/ scripts (~17 min CPU)
./scripts/pairs.sh ../.. ref/tidyABM 3   # interleaved A/B timing against the reference
```

Run `Rscript -e 'pkgload::load_all("../..")'` once first so the Rust library is
built before anything is timed.

# Working on tidyABM's Rust code

tidyABM is moving its engine to Rust under the unchanged R grammar. The plan, its
decisions and the phase results live in `sandbox/rust-migration/PLAN.md` (outside
this repository). The work lives on the `rust` branch until phase 4; `main` stays
pure R.

## Layout

| path | what |
|---|---|
| `src/rust/Cargo.toml` | the savvy bridge crate `tidyabm` (R entry points) and the workspace |
| `src/rust/src/lib.rs` | the `#[savvy]` entry points; each body runs under `run()` (panic guard) |
| `src/rust/src/rapi.rs` | hand-written declarations of R's public C API (RNG, Rmath) and of `src/reduce.c`; `protect()` |
| `src/rust/src/rng.rs` | `with_rng()` / `RRng`: R's own generator from Rust, main thread only |
| `src/rust/src/reduce.rs` | safe wrappers over the long-double C helper |
| `src/rust/src/store.rs` | the column store's R side (`AgentStore`): loading groups, exporting them, the write API `set_col()`, the string pool, the mirror cache, snapshots, stacking the result |
| `src/reduce.c` | long-double sums, means, cumsums, group sums (Rust has no long double) |
| `src/rust/tidyabm-core/` | engine code with no R dependency; `cargo test` runs here (`sample.rs`, `reduce.rs`, `store.rs`, `neighbours.rs`, `expr.rs` the evaluator) |
| `R/rust-blocks.R` | `rust_rng_ok()` (verified `RNGkind()`s) and the R-side wrappers with their R fallbacks |
| `R/run-rust.R` | the Rust run path: `run_once_rust()`, the step adapter, kernel dispatch and replay (`rust_step()`), "both" mode |
| `R/rust-kernels.R` | the step kernels (`rk_*`) and their registry `rust_kernels` |
| `R/rust-expr.R` | the expression compiler (`rx_compile()`), the compiled-rule kernels `rk_rules()` / `rk_global()`, `rx_coverage()` |
| `src/rust/src/expr.rs` | `RxProgram`: decodes the IR, reads R's columns in place, R callbacks for draws and `exp`/`log`/`sqrt` |
| `src/rust/Cargo.lock` | pinned crate versions (committed) |
| `src/rust/vendor.tar.xz`, `vendor-config.toml` | all crates for the offline build (committed) |
| `src/rust/deny.toml` | licence / advisory policy for cargo-deny (CI) |
| `src/Makevars.in`, `Makevars.win.in` | build templates; `configure` / `configure.win` fill them |
| `src/init.c`, `src/rust/api.h`, `R/000-wrappers.R` | generated by `savvy-cli update`; do not edit |
| `R/engine-switch.R` | `options(tidyABM.engine = )` and `rust_call()` (Rust errors to R conditions) |
| `tools/vendor.sh` | rebuilds `vendor.tar.xz` and `inst/AUTHORS` |
| `dev/oracle/` | the frozen oracle every migration step is checked against |

## Toolchain

* Rust through rustup (<https://rustup.rs>), stable channel. The minimum supported
  version is 1.81 (`rust-version` in both `Cargo.toml`; savvy 0.11 needs it). CI
  builds with 1.81 too.
* `savvy-cli` 0.11.0, the same version as the `savvy` crate:
  `cargo install savvy-cli --version 0.11.0 --locked`. It ends up in
  `~/.cargo/bin`; put that on `PATH` or call it by its full path.
* R >= 4.2 and the usual devtools set.

## Everyday loop

```sh
# after changing an entry point's signature or adding one (src/rust/src/lib.rs):
savvy-cli update .                    # from the package root
# load and test from R (builds the Rust library into src/, about a minute the first time):
Rscript -e 'devtools::load_all(); devtools::test()'
# Rust only (from src/rust):
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p tidyabm-core
```

`load_all()` decides whether to recompile from the C files in `src/` only, so after
editing `.rs` files run `touch src/init.c` before the next `load_all()`; otherwise it
keeps the old library. **`load_all()` builds the Rust library unoptimised** (pkgbuild
passes `DEBUG=true`, so `configure` picks cargo's `dev` profile): Rust code then runs
10-20x slower (the neighbour fold: 100 us instead of 6). Before timing anything, and
in any shell that runs the oracle, `export SAVVY_PROFILE=release` and rebuild
(`touch src/init.c`); `grep PROFILE src/Makevars` says which one the last build used.
Any later `load_all()` that recompiles without that variable goes back to `dev`. Avoid `pkgbuild::clean_dll()`: it also deletes the `.a` files
that cargo's build scripts left under `src/rust/target` (savvy's
`libunwind_protect.a`), and the next build fails with "could not find native static
library `unwind_protect`" until `src/rust/target` is removed.

Run `cargo clippy` / `cargo build` with a target directory of their own
(`CARGO_TARGET_DIR=/tmp/tidyabm-target cargo clippy ...`): a dev build in
`src/rust/target/debug` can leave a `libtidyabm.a` that the next `load_all()` links
without savvy's C helper (`symbol not found: _unwind_protect_impl`); deleting
`src/rust/target/debug` fixes it.

The savvy crate's own tests do not link without an R session; test entry points
from R (`tests/testthat/test-rust-*.R`) and keep logic in `tidyabm-core`.

Rules the code follows (PLAN.md section 1):

* Every `#[savvy]` body runs inside `run(|| ...)`. It installs a silent panic hook,
  catches the panic and returns its message as an error, so a panic becomes the R
  condition `tidyABM_rust_panic` and never unwinds into R. savvy's own hook prints
  through R from whichever thread panicked, which is forbidden on worker threads.
* No R API call from a worker thread. Workers get plain Rust data; results and
  panics come back through `join()`.
* Rust never formats what the user reads. It returns an error message with a prefix
  (`ERROR_PREFIX` / `PANIC_PREFIX` in `tidyabm-core`); `rust_call()` in R raises it
  with `abm_abort()` and a class.
* Every `unsafe` block has a `// SAFETY:` comment.
* **No code copied or ported from R's sources** (GPL; decision D13, the package is
  MIT). R's generator and math are reached only through R's public C API
  (`GetRNGstate`/`PutRNGstate`, `unif_rand`, `norm_rand`, `exp_rand`,
  `R_unif_index`, the Rmath `Rf_r*` functions, `R_pow`), declared by hand in
  `rapi.rs`. Behaviour that is not in the API (the long-double sums, mean's second
  pass, `sample.int()`'s algorithms) is written from R's documentation and pinned
  down by differential tests against R, never by reading R's C sources. Where
  neither works (weighted `sample()`, R >= 4.5's `exp`/`log` wrappers), the R path
  is used.
* R's RNG only inside `rng::with_rng()`: it loads the state with `GetRNGstate()`,
  hands out the `!Send` token `RRng`, and writes the state back with
  `PutRNGstate()` on every exit (return, error, panic). Never draw on a worker.
* Any call that may raise an R error or warning (`GetRNGstate`, `PutRNGstate`,
  Rmath functions, `R_pow`, which warns for huge exponents) goes through
  `rapi::protect()`: a warning turns into a longjmp under `options(warn = 2)` or an
  exiting `tryCatch(warning = )`, and a longjmp must never cross Rust frames.
* The Rust path draws only under the `RNGkind()`s the tests verified
  (`rust_rng_ok()`); every other kind, and every parameter for which R would warn,
  takes R's own function.

## The engines and the column store (phase 3)

`options(tidyABM.engine = )`: `"r"` (default) is the R engine; `"rust"` keeps the
run's groups in the Rust column store (`AgentStore`) and runs each step through its
Rust kernel (`R/rust-kernels.R`) or, while none exists, through the *step adapter* (the R engine's step
function over the store's groups, loaded back afterwards); `"auto"` takes the Rust
path only when some step has a kernel registered with `auto = TRUE`; `"both"` runs every step on the R engine and
on the Rust path from the same state, `.Random.seed` and caches, and stops at the
first difference (`tidyABM_engine_mismatch`, naming step, tick, group, column, row
and both values). A kernel is `function(step, state, store)` registered in
`rust_kernels` (`R/rust-kernels.R`) under the step's class; test it with
`TIDYABM_ENGINE=both` over the test suite and the oracle (`TIDYABM_ENGINE=both
./scripts/verify.sh`, the same for `models.sh`).

Store rules: doubles, integers and logicals keep their bits; a character column is
codes into a pool of R's own `CHARSXP`s; a typed column's attributes (factor
levels, classes, names, dim) live on a zero-length donor and come back with
`SHALLOW_DUPLICATE_ATTRIB()`; list, complex, raw and data-frame columns are opaque
preserved R objects. Every column, group and the group list keep the R object they
came from (the mirror): `export()` hands it back while Rust has not changed the
column, and `load()` copies only columns whose object changed. `set_col()` drops the
written column's, its group's and the list's mirrors in one place.
Results are stacked in Rust when every column is a plain typed vector of one type,
otherwise by R's own `bind_rows()` over the recorded groups.

## Step kernels (phase 4)

A kernel is `function(step, state, store)` in `R/rust-kernels.R`, registered in
`rust_kernels` under the step's class with `auto = TRUE` only once it is proven in
"both" mode **and** measured faster than the R engine on paired runs. Rules:

* Follow the R engine's step function line for line where it does R work (same
  helpers, same `planned()` keys, same `state` fields such as `nb_cache`): "both"
  compares the whole `state`, not just the groups.
* Decline (`return(NULL)`) before changing anything for any shape the kernel does
  not take; the step then runs through the adapter from the original state and
  `.Random.seed`.
* Write columns only through `store$set_col(group, name, values)` (it drops the
  column's, the group's and the list's mirrors), then set
  `state$groups <- store$export()`. `values` must be what `assign_rule()` would
  have written over every row (bare, unnamed, one value per row).
* Never print. Outside "both", a kernel that errors, warns or messages is replayed
  on the R path (`rust_step()`), so the user sees R's own condition exactly once;
  under "both" the same thing is a mismatch, so kernel faults are caught, not hidden.
* `options(tidyABM.rust_kernels = c(neighbours = FALSE))` turns a kernel off
  (step class without `abm_`).
* Rust code reads R vectors through `store::numbers_of()` (no copy; ALTREP data is
  materialised inside `protect`) and returns `NULL` (decline) for anything it does
  not handle bit for bit (for example sums that meet `NA`/`NaN`, whose payload choice
  is `rowsum()`'s).

The store outside "both" is brought up to date only when read: the adapter marks it
stale (`sync$ok`), and `run_once_rust()` loads `state$groups` before a kernel or a
recorded snapshot. Under `use_mirror` a loaded typed column is kept as R's vector and
copied into Rust only for a snapshot that may reach the result (lazy copy-in).

## Compiled formulas (phase 5)

`abm_rules()` (no `.by`, nothing read of a pairing, no pairing splitting the rows,
no relation) and `abm_global()` (no `.by`, more than one group) evaluate their
formulas in Rust when every formula of the step is in the grammar of
`R/rust-expr.R` (see its header and `rx_coverage(go)` for the reason a rule is not).
How it fits together:

* `rx_compile()` turns a formula into nested lists once per session; `rx_program()`
  binds names to input slots for a group (column, then global, then the formula's
  environment, as the R engine's mask finds them), checks that every function name
  finds the standard function, and builds an `RxProgram` (kept per session).
* `RxProgram$eval(inputs, n, out_n, stacked)` evaluates the rules in order and
  returns R vectors, or `NULL` with the reason in `rs_rx_reason()`. Rust never
  warns: wherever R would warn, error or give bits Rust cannot reproduce exactly, it
  returns `NULL` and `rust_step()` replays the step on the R path from the saved
  state and `.Random.seed`.
* Typing is R's and vctrs', decided per call from the data (`tidyabm-core/src/expr.rs`).
* Kernels that work on `state$groups` (not the store) are registered with
  `store = FALSE`; `rust_step()` then marks the store stale instead of loading it.
  A step whose formulas can never compile is marked `rust_no` in its plan and goes
  straight to the adapter afterwards. `can(step)` tells "auto" whether a run has
  anything a kernel can take.

Adding a function to the grammar: add it to `rx_fns()` and `rx_compile()` (R), to
`decode()` (`src/rust/src/expr.rs`) and to `Node`/`eval()` in
`tidyabm-core/src/expr.rs` with a cargo test; then extend `rx_random_expr()` in
`tests/testthat/test-rust-expr.R` so the property test (3,000 random formulas with
`NA`, `NaN`, `Inf`, `-0`, integer extremes, strings) covers it, and run the suite
under `TIDYABM_ENGINE=both`. Behaviour comes from R's documentation and
differential tests only (D13): for example, integer `/` gives R's `NA_real_` for an
`NA` operand, `pmin(0, -0)` keeps the first, dplyr 1.2's `case_when()` sizes its
conditions and values apart. Measure with `SAVVY_PROFILE=release`: a kernel step
costs ~25-30 us of R-side overhead before any evaluation, so a formula R already
evaluates in a few microseconds is not worth compiling (one-group `abm_global()`
steps decline for that reason).

## Vendoring (offline builds)

`R CMD INSTALL` builds offline from `src/rust/vendor.tar.xz` whenever that file
exists (`cargo build --offline -j 2` with a private `CARGO_HOME`), as CRAN requires.
So **after changing any dependency or `Cargo.lock`, re-vendor**, or the install
fails:

```sh
sh tools/vendor.sh                    # from the package root; needs network once
```

It rewrites `vendor.tar.xz`, `vendor-config.toml` and `inst/AUTHORS` (crate, version,
licence). Check that every licence is MIT or Apache-2.0 compatible; CI's `deny` job
checks it with cargo-deny (`cargo deny check` in `src/rust` if you have it installed).

Proving the offline build locally:

```sh
R CMD build .
mkdir -p /tmp/empty-cargo-home
CARGO_HOME=/tmp/empty-cargo-home R CMD check --as-cran --no-manual tidyABM_*.tar.gz
```

## The oracle

`dev/oracle/` holds the frozen goldens (README there). Before and after any change
to engine code, from `dev/oracle/`:

```sh
./scripts/verify.sh                   # tests, 291 harness cases, vignettes, benchmarks (~3 min)
./scripts/models.sh                   # the 68 models/ scripts (~17 min CPU)
./scripts/pairs.sh ../.. ref/tidyABM 3   # interleaved A/B timing against the reference
```

Run `Rscript -e 'pkgload::load_all("../..")'` once first so the Rust library is
built before anything is timed.
